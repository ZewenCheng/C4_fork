# 云端部署回归测试报告

## 1. 模型血缘纠正

通过读取初赛原始执行记录，确认冻结五编码器实际调用为：

```text
facebook/dinov2-large                  → DINOv2-L 1024维
facebook/convnextv2-large-22k-224      → ConvNeXtV2-L 1536维
google/siglip2-so400m-patch14-384      → SigLIP2 1152维
timm:eva02_large_patch14_448...        → EVA02-L 1024维
官方Qwen3-VL-Embedding-8B              → 4096维
```

旧归档README把部分缓存错误地写成timm DINOv2-B和timm SigLIP基础模型；这些缓存只能支持部分历史训练，不能重建冻结特征。本云端包已改用上述准确权重和Transformers预处理。

## 2. 两张原始图片逐编码器验证

测试路径从官方原始数据目录读取，程序在内存中重建初赛1024像素JPEG，再进行三视图特征抽取。

| 分支 | 与封存特征比较 |
|---|---|
| Qwen | 最大绝对误差 `7.45e-9` |
| Google SigLIP2 | 逐元素一致 |
| Facebook DINOv2-L | 逐元素一致 |
| timm EVA02-L | 逐元素一致 |
| Facebook ConvNeXtV2-L | 逐元素一致 |
| expQ全量特征 | 最大绝对误差 `2.34e-5`，来自设备浮点末位 |

## 3. 300张初赛测试图全链验证

执行链：

```text
官方原图
→ Qwen模拟官方接口（返回封存Embedding）
→ 四个本地视觉骨干重新推理
→ expQ原始FP32全量权重重新推理
→ 可移植LR系数推理
→ result.json
```

结果：

- 特征矩阵：`300×8832`；
- expQ特征：`300×1152`；
- 可移植LR输出与历史expQ：`300/300`一致；
- JSON结构校验：通过；
- 测试图人工查看与逐行修改：0。

因此，本包已验证能够从原始新图片入口恢复初赛expQ，而不是仅重放封存特征。

## 4. 云端继续训练冒烟

在2张官方训练样例上执行1 epoch：

- expQ最后4块、norm和22类head成功更新；
- 生成云端delta检查点；
- delta重新加载成功；
- 无MPS/CUDA路径硬编码错误。

该冒烟只验证程序链路，不代表2张样例的模型效果。正式决赛必须在云端训练/验证划分上重新评估。
